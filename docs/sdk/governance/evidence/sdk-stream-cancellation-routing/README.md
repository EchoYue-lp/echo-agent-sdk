# Original extension stream cancellation route lifecycle

This candidate fixes only the three language clients' transport cancellation addresses. Framework Task/Run/physical settlement authority and wire/API schemas are unchanged. The parent is independently reviewing cancellation beyond grace and actual physical producer settlement; the passes below do not close that framework obligation.

## Root cause and repair

The original callback returns a valid stream setup ACK while its native producer continues. All three clients unconditionally removed `invocation_id -> cancellation` in the callback's finally/doFinally. The Host's later typed cancellation notice therefore found no route and the native producer never received its signal. In the true Task pause case this kept the first Agent stream open and the resumed invocation failed the existing exclusive lease. The separate original boundary timeline is `../task-resume-early-ack-cancellation-root-cause/README.md` (actual setup deletion followed by the same Host cancellation ID lookup returning false).

The client now retains that original invocation address only for its declared matching stream, keyed by the complete Host-minted stream `(id, generation, kind)` and extension owner. The address is captured before callback execution, so a valid declared stream remains addressable even if cancellation arrives before its setup response is normalized to Cancelled. Ordinary/nonstream/error setup paths roll back their address as before. A terminal that successfully completes the official notification submission removes only the matching stream's original route. Sending a terminal before the callback response removes it once; the response never recreates it. Wrong stream IDs/generations/kinds and failed terminal sends cannot release it. Successful unregister removes matching owner routes; an unregister failure leaves them. Client close signals cancellation first, with Python/Java retaining routing after a failed teardown and clearing only after successful native close. TypeScript closes its actual official connection, whose closure clears those transport addresses.

There is no scheduler, public stream cancellation feature or alternate Task state machine. Normal setup ACK still returns immediately. This address ledger tracks where a later wire cancellation is delivered; it does not assert that a declared terminal covers cleanup the user's callback detaches after that terminal, or that a successful registry unregister alone proves external physical work ended.
