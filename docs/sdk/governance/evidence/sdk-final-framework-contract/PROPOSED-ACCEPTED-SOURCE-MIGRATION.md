## Security migration requirements

The seven security keys form one semantic group. The root facade still re-exports all original names, so simply returning FeatureUnavailable for those seven would remove supported behavior and is not this proposal. Exact source relocation should preserve public aliases, type fields, input/result shapes and errors. The single producer's current new-acceptance gate accepts only reviewed deferred sources; it must not be weakened broadly to admit all Rust/Host-only APIs. Before execution, verify each fresh canonical destination's classification and decide whether paired exact deltas already satisfy the existing rule or a narrowly reviewed source-migration mechanism is necessary. No such producer permission change is made here.

The current Host source-operation dispatch matches the old three `echo_agent::security::*` defining keys. After unique generation resolves actual new operation strings, the responsible Host owner must map both old public facade requests and generated canonical destinations to the same original functions, with targeted native proofs. This is an adapter routing requirement, not permission to create another scanner/redactor. Old facade aliases must not be silently dropped just because new canonical source keys exist.

## Evidence limits and rollback

`docs/sdk/governance/task-subagent-evidence.md` and its source tests prove scoped pause/cancel, canonical Task results and exact backend CAS behavior. They explicitly do not prove that every TaskSubagentContext field is directly projected as a complete reverse DTO into CustomAgent callbacks. The actual Host adapter consumes the three getters; this proposal cannot inflate that source evidence into a nonexistent native field receipt. Framework's full gates and ADRs justify authority convergence but do not independently approve retirement of SDK accepted source keys.

The core current rustdoc observation and old contract closure are retained in `security-current-rustdoc-observation.json` and `complete-missing-source-closure.json`. There is not yet a final native proof for the newly generated security routes because full generation has intentionally written no artifacts. Supporting typed DiagnosticCode additions are separate already-approved exact dispositions; Channel wrapper and Task getter identities remain outside this proposed language acceptance scope.

Rollback is atomic at the contract boundary: restore the prior complete accepted contract/catalog/schema and matching framework pin/lock together, rebuild the matching Host, and revalidate its native clients. Do not rollback only a source key while retaining incompatible route digests; do not reactivate obsolete snapshot or claim-writable runtime authorities. Raw current and historical evidence remains immutable and is not relabeled as proof of the rollback snapshot.

## Next decision

The parent will bind one explicit decision for: (A) seven one-to-one security defining-source moves preserving old aliases and behavior; (B) three old writable Task context field identities retired while existing getter-based Host behavior remains; (C) two obsolete snapshot fields retired with explicit unsupported status while canonical Skill and Task/Plan obligations remain. Until that finite decision and its exact ADR sections are approved, no seed, generated artifact, producer acceptance rule or Host source is modified by this lane.
