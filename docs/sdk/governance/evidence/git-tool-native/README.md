## Boundary and oracle

The `source-abi/` files archive exact framework `a634` tool declarations. Host `bind_parameters` iterates the framework's `properties` in their declaration order. The generated facade catalog exposes `WireValueArray` and operation signatures; it does not contain parameter-name ordering. The fixture's positional key lists therefore follow these archived declarations, checked by real Host outputs, rather than inventing catalog metadata.

The test repositories remain under the LP project. Fixture configuration sets local author identity, `commit.gpgsign=false`, stable author/committer dates and an owned-directory discovery ceiling. Only explicitly named owned fixture steps stage/restore files or create a local fixture commit. No user repository, remote push, SDK public contract or production permission setting is changed.

The three meaningful groups are:

1. Reads, branch create/switch/delete, invalid references and non-repository failure, including preservation of same-name dirty content.
2. A partial `git add` failure preserves dirty file bytes and HEAD while its earlier valid path remains staged. A subsequent Host commit consumes staged content. The test does not promise automatic index rollback.
3. Managed worktree metadata/list/explicit cwd, refusal to remove dirty content, clean removal preserving its branch, and the four accepted source create/list/merge/remove operations with a real local merge.

Full response and error objects are retained. Cross-language comparison replaces only each owned root path; it preserves every other result, error, ref, staged entry, tree and file field. This fixture does not establish concurrent branch mutation, remote push, or merge-conflict recovery. Framework tests cover the latter separately.
