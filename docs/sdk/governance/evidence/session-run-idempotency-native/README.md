The common scenario and oracle check five groups per language:

1. Same Agent/key/canonical Session payload returns the identical complete response for repeated/concurrent calls, with one actual persistent Session-index record. Changed cwd conflicts before a new creation.
2. A registered native provider is held in its original callback. The same Run key replays the identical complete response while active, after completion and after public local RunHandle.close, with one provider call and no repeated event notification. The complete terminal receipt remains raw. Optional `first_event` was absent in all actual original responses; it stays absent, with no synthesized replacement.
3. Another Agent/Session has an independent key scope and a distinct Run/stream, with exactly one additional provider call.
4. An unkeyed active Run makes a new keyed start fail before effect admission. After it settles, the same previously rejected key successfully starts another Run. Counts are one provider call while rejected and exactly two after retry. The earlier busy rejection must not be retained as a completed publication.
5. After original Session closure, both its Session key and Run key return `closed_handle`; neither recreates resources. The full original owner handle/generation and actual error operation are retained. In particular, the closed Run owner error's operation is `_echo_agent/session`, not a rewritten run/start label.
