# Managed三项逆向操作的合同边界

现有managed bridge声明11个typed反向operation。真实native主路径已证明八个；剩三项不是新增SDKforwardAPI，也不能因DTO存在虚构consumer成功。

|逆向操作|实际framework消费者与权威|当前SDK接受边界|产品处置|
|---|---|---|---|
|conversation_delete_managed_with_context|delete_persisted_conversation_managed_with_context持caller稳定ManagedConversationDelete，调用ConversationStore原commit权威|当前accepted兼容delete_persisted_conversation对managedpair明确ManagedStateRequiresCas，副作用前拒绝|保reverse DTO/adapter/supporting值与Rust/Host stabledelete，不新增forward调用承诺|
|runtime_begin_scope_retirement_with_context|同framework stabledelete先载scopeauthority、prepare稳定retirementrequest并begin|accepted clear_persisted_runtime_incarnation只retire指定generation，不调用scope retirement|保reverse DTO/adapter；scope manifest与CAS保framework权威，不造SDKscope删除器|
|runtime_continue_scope_retirement_with_context|同stabledelete保存conversationreceipt、逐generation advance、最后complete|兼容delete拒managed，generationclear不advance整个scope|保reverse DTO/adapter；新的SDKforward stabledelete暂未接受，不默认成功/默认revision|

这些逆操作在framework有实际调用路径，不是死能力。代码核对绑定77de main的src/state/mod.rs blob与当前读取字节精确相同；SDKdispatcher/canonicalaccepted输入和Protocoloperationenum另保存hash/摘录。证据见[evidence/sdk-deferred-product-disposition/managed-three-operation-boundary.json](evidence/sdk-deferred-product-disposition/managed-three-operation-boundary.json)。这是源码与合同范围取证，不称三项新增native正向场景已运行。

保留11种typed逆调用schema义务：字段/整数/optional/deadline/cause无损、backend未广告能力明确Unsupported、unknowncommit不默认成功。接受的reversevalue与Rust/Host caller不自动接受其任意forwardhelper。实际八consumer绿与Unsupported行为保原7bbd证据；最后三项主能力承诺不能由直接人工invoke逆DTO“补绿”，也无需新增未接受forwardAPI。若以后明确接受稳定manageddelete，必须保caller持久请求、唯一frameworksettlement和完整scopeCAS，接受后再补真实三语言consumer，不能语言侧复制retirement状态机。

这项分层已经可由当前源码与合同确定，不需要新的用户裁决。Finding中原字段适配/失败签名的修复、验证及独立复审条件仍按精确缺陷收口；最终全11consumer不是当前合同强造的新门槛。
